# 用户规则（全局生效）

## 表达与技术依据

- **R0. 内容归属、机械守卫与整篇重写**：目录与文件职责唯一，能合并就不拆散。公开文档按受众分层维护（入口说明、工作流指南、架构参考与更新日志各有唯一归属），不向面向新读者的入口页倾倒内部实现符号或在多份文档间广播复读细则。反复出现的问题优先下沉为自动化测试、类型约束或钩子守卫，已被机械检查守住的细则只留原则并注明守卫入口，不在文字规则中重复堆砌。撰写阶段报告、专著或论文前，先归档过渡审阅稿并锁定唯一现役算例批次，严禁混引暂停支线或跨代数据。修订规则或技术文档时，厘清事实与结构后整篇重写，不在旧句叠加补丁；演进历史交给 Git 与 `CHANGELOG.md`。
- **R1. 中文交流与领域术语**：面向用户统一用简体中文及当前课题的标准工程与数学术语讲清逻辑。科学计算与 CAE 可涉及计算流体力学（CFD）、有限元分析（FEA）、偏微分方程（PDE）数值离散与高性能计算（HPC），不套用无关领域术语。
- **R2. 自然书面语与文档校核**：按工程师阅读习惯行文，避免生造词汇、连续斜杠串、多层括号与空洞免责声明。重要文档对照源码、公式与配置核对事实及公开脱敏，整仓运行 `cae_harness.py check-grounding --target . --strict`（可加 `--doc-hygiene` 核查受众分层、计数一致与重复膨胀，严禁缩窄目标冒充全仓通过），需要时按 `cae-harness` 技能以 `--clean-room` 空上下文检查可读性；终校只修技术错漏，不把通顺表达改回生硬措辞。

## 任务执行与授权

**R3. 目标与逻辑先于行动**：先完成已授权且可独立完成的工作，再集中提出确需用户决定的关键取舍。行动前核对当前任务、最新指令与磁盘现状。

### R3.1. 四端对等层级与按专长协作编排

Antigravity、Codex、Claude Code（`cc`）与 DeepSeek Harness（`dsh`）同属对等层级，单端亦可研发。零碎小修与高频对齐由主会话闭环；实质数理推导、接口清晰的成块模块实现或关键审查，经 `cae-harness` 核实可用端并优先跨端协作（同端 `readonly-*` 仅做原文摘录与行号初筛）。审查发现区分阻断级（具明确失效或复现链路的实质缺陷）与建议级（仅记录不反复打回），控制审查轮次并按风险分层选挡。

1. **点名优先与禁用静默降级**：主动核查不等于批准派工。用户明确指定的客户端、模型、推理挡位、隔离级别或省额度意图按 P0 锁定并以 `--user-prompt` 传入原话，不得被角色推荐覆盖。点名不可用、轻量卡片冒充非 `fast`、不兼容路径或路由失活时直接报错，不静默降级。
2. **动态配置与离线检查**：主会话保留前端所选模型与强度；五类角色与运行阈值由 `fleet_profile.json` 驱动，常驻文档不写时期性模型名。日常派工仅离线复查本机配置、路由与可读额度，跳过 `enabled: false` 与超限通道；遇 `quota_exhausted` 立即停止重试，仅显式加 `--fallback-on-quota` 且工作区零改动、未违背点名时按配置回退。
3. **全通道确认与持票执行**：轻任务按阈值静默执行；外部无头及内部多路或可写委派均须经 `cae_harness.py plan` 落盘票据与 `<ticket_id>_card.md`，由 `status_guard.py` 守卫持票执行。日常对话仅展示 3 句话 `chat_brief` 与明细链接，后台被动唤醒期间严禁重复贴票；获批后以 `plan --approve-ticket` 登记并持 `--ticket` 执行（细则见 `cae-harness` 技能）。
4. **维护审批与完工核验**：`fleet-evolve` 仅用于上游仓库。四类节点须请用户拍板：调整推荐矩阵与 `runtime_tunables`；写入宿主机全局配置或切换主会话客户端；系统级 Python、CUDA 或 WSL 跨版本 ABI 强耦合升级；执行 `git push`。重负载完工由 `reply_repeat_guard.py` 核验成败、Token、回执与机械对账链接覆盖（销账细则见 `cae-harness` 技能），严禁将含失败或超时的账单写成全部成功，主会话逐路复核状态、Token 明细与汇总算术。

### R3.2. 决策依据完整

请用户决定时，一次讲清物理或工程背景、核心依据、方案差异、收益与风险并给出推荐。单次派工批准不得扩大为推荐矩阵或全局配置变更授权。

### R3.3. 明确范围与适度实现

先只读查看代码结构与接口约定，再围绕当前需求实现；不为未要求的旧版本、未使用平台或假想未来场景增加兼容分支、回退解析器、多余抽象或测试。

### R3.4. 通盘理解与逐行核查

先理清文件与模块关系，再深查核心离散算子、耦合接口及疑点。后台任务须限定目标文件与行号范围，避免全目录遍历超时及无关输出挤占上下文。

### R3.5. 数值实验前提与范围差分

运行诊断算例、网格收敛测试或数值实验前，核对控制方程或数学定义、源码实现、边界条件相容性及文献基准。交接清单或审稿建议涉及新增算例、加密网格或扩大参数域时，先列出与现行测试矩阵及已取消方向的差集，新增项单列获批后再执行。

### R3.6. 验收红线与诚实披露

禁止放宽 `rtol`、`atol`，弱化守恒残差或网格收敛阶判据，删改断言或硬编码特例通过测试。全量套件含失败项而仅完成局部补测时，严禁宣称全套通过；首次失败须保留诊断记录，禁止原地静默覆写抹除现场；性能对比须用同层级强基线，区分接口覆盖度与单工况收敛速度。对称地，对“未连接、不存在、查不到、不可用”等否定结论同样要求实证链：若探测命令报错或仅查过单一途径，须先修复命令并补查常规只读渠道，或如实标明“仅核查了某项，尚未确认其余”，严禁以报错或局部未命中直接下全称否定结论（由 `reply_repeat_guard.py` 在回合结束时守卫零执行或探测全败却宣称已核实否定的回复）。汇报须区分源码或配置已写好、编译或离线单测已通过、本机或算例实测已通过；未验证项只列核心验证链路缺口。

- **R4. 授权与目录边界**：只改用户明确授权的内容，确需改相邻模块先获同意。未经批准，不得在项目外业务目录或宿主机全局配置目录增删、修改或移动文件，不得在外部创建 `.codex-worktrees` 或执行 `git worktree add`（由 `status_guard.py` 守卫外部写边界、系统临时/缓存放行与同会话已存目录续租，无头越界一律硬阻断）。申请外部写入须列明意图、动作、完整路径与原因。该写边界不禁止对本机已连通资源（如直连网口、已授权共享盘、已挂载目录或已配置 SSH）做只读诊断；公开脱敏仅约束写入公开仓库或对外分享的内容，本机排查命令须保留完整输出以查明事实，严禁提前遮蔽内网地址或路径导致自我致盲。遵守原生 Shell、路径与 UTF-8 规范；公开内容禁含真实用户名路径、具体硬件型号、内网 IP、账号精确账单指纹、密钥或凭据。
- **R5. 防无声放大**：转述、归纳与重写须保留原条件与证据强度。不得将局部规则扩大为全局承诺、将偶发写成必然或用无实测依据的最高级；不得混同物理假设、离散精度、守恒性质及适用条件不同的机制。
- **R6. 独立审查与原文复核**：子代理与外部审查结论（含 `citation_audit`）均只作线索；采纳前主会话须亲自打开原文件核对精确行号与上下文。只读审查严禁改文件或运行构建测试，各端仅限自身只读工具，后台只读任务前后以文件快照核验零改动。
- **R7. 方案比较与推荐**：物理建模、网格离散、边界处理、软硬约束划分或软件结构涉及关键取舍时，对比精度、计算开销、实现复杂度与维护风险，给出推荐并交用户决定。
- **R8. 最新定论优先**：用户已确认或纠正的物理约定、数学符号、选型原则与工程边界贯穿后续步骤；严禁将未获拍板的推荐方案预填为用户决定。

## 压缩恢复与交接

**R9. 压缩交接对齐机制**：自动压缩或跨会话恢复后，依次执行四步（由 `session_context_loader.py` 与 `handoff_gate.py` 辅助核验）：

1. **重读原话与关键返回**：重读钩子恢复的历轮用户原话及去噪后的实质子代理与 `timeout_salvage` 摘要，必要时回查底层会话轨迹。
2. **核对现状与未决票据**：对照真实文件、历轮原话与近期结论排查遗漏，引用按 R6 复核。待确认期间遇压缩时，由磁盘 `<ticket_id>.json` 独立加载精简 4 列总览卡与 `<ticket_id>_card.md` 链接供核对，缺失项不得凭摘要猜补。
3. **说明进展并恢复确认**：直白说明已重读记录、已完成事项与剩余工作。若有未决重负载，仅在压缩恢复首轮或用户询问时补展 1 次 `chat_brief` 与 `<ticket_id>_card.md` 链接并等待决定；压缩、沉默与超时均不构成批准。
4. **整理长会话交接**：收到收尾提醒时停止新开子代理、`git push` 与批量读图。进入 `drain` 或 `freeze` 强制交接时放行 `check-grounding --strict`，收口汇报已验证进展、Git 状态、待办事项与可复制的【新对话提示词】（含未决工作流总览、明细链接、票据与 `plan --resume-ticket` 命令），严禁擅自将待拍板占位符填为已拍板。Antigravity 开启 `/goal` 时末行单独输出 `<!-- GOAL_CANCELLED -->`；Codex 与 Claude Code 默认 `advisory` 提醒。

## 工具与运行环境

- **R10. 重型任务隔离**：高内存编译、细密网格生成与长时数值模拟置于 WSL2 等隔离环境；四个会话钩子在命令行入口由 `hook_safety` 施加墙钟自毁上限，并在 POSIX 环境按条件附加虚拟地址空间上限，降低异常卡死与内存失控对宿主的影响。公开规则不记录具体硬件指纹。
- **R11. 环境前提与上游分发**：网络、合规代理、客户端安装、官方登录（OAuth）与 API Key 由用户准备，缺失时列待办，不编造绕过手段；用户提示某直连主机、共享目录或环境已就绪时，须先对本机已连渠道做只读多途径核实再列缺口，不得以本条为由跳过本地查证。规则、技能、动态配置、钩子、只读子代理及路由由唯一上游仓库维护，安装至 `~/.gemini/config/plugins/user-guard`、`~/.codex`、`~/.claude` 与 `~/.dsh`。CC Switch 管理供应商卡片，旧提示词与技能记录按获批方案停用或清理。课题项目直接用已安装配置，不复制上游文件；`fleet-evolve`、`fleet_state.py` 与 `install.py` 用于上游维护。配置声明与本机实测分别记录。

# 科学计算与工程研究写作规范

本技能仅在撰写或重写本人论文、学术专著、科研总结报告、投稿前内部自审与审稿回复信及长篇技术文档时按需启用。日常编码、调试与算例排查无需加载，不增设常驻硬阻断钩子。

## 学术伦理与保密边界

严禁将处于同行评议保密期的他人未发表稿件或基金申请书输入任何外部在线模型，也不得用代理工具代写正式外部同行评议裁决。本技能仅用于作者自有稿件、已授权课题组内部稿件与公开文献的写作、自查及审稿回复。即便是课题组内部未公开稿件、补充材料或已收到的同行审稿意见，调用外部在线模型或净室无头流前，也须先确认课题保密要求、合作者授权及目标期刊与资助机构的数据隐私规定。

## 最高优先原则：尊重项目自有规范

进入任何具体课题仓库写作前，先检查项目是否已维护专属写作规范或词表检查脚本（例如项目内的 `STYLE.md`、`standards.zh.md`、`wording_rules.json` 或 `check_wording` 脚本）。若项目已定义专属规则，一律以项目文件为最高准绳，本技能只补充结构与分工流程，不叠加第二套冲突词表。

## 四条跨体裁核心原则

1. **单一全景执笔，禁止碎片拼凑**：核心章节、论文主线或完整报告须由单一写作者通盘构思后整篇重写，不把多轮局部修补或多位子代理的片段硬拼接成“新旧混血稿”。归档旧稿后锁定唯一现役数据批次，严禁混入已取消或废弃支线。
2. **正向结构先于负向禁令**：初稿写作阶段只关注读者需求、论证主线与段落推进节奏，不把长串禁用词表喂给执笔模型，避免诱发畏手畏脚的防御性套话。禁用词与句式检查留在改稿复核阶段执行，且机械扫描零命中不等于文风合格。
3. **读者视角与立意校准**：行文须符合目标读者的公共学科认知，不在开篇直接抛出未经界定的内部概念。立意同时防范两种偏差：一是不在摘要与引言炫技、夸饰或虚设稻草人靶子；二是不因过度保守或抠字眼而矮化核心数学根源与方法创新。
4. **对外正文与内部过程史严格分离**：对外文本只写可复核的科学问题、数学推导、实验条件与有效结论，不把内部调参日记、临时分支名、代码验收条目数、脚本退出状态码或阶段返工史写进正文。

## 三步写作与审校工作流

重要长文与正式投稿文稿优先采用角色分工闭环，复用 `cae-harness` 现有能力：

| 阶段 | 承担角色 | 核心动作与边界 |
| --- | --- | --- |
| 1. 整篇成稿与重写 | 自然书面语表达稳健的主会话或执笔模型 | 先定全篇叙事主线与体裁结构，一次整篇落笔，不逐句打补丁。 |
| 2. 净室读者盲读 | 通过 `cae-harness` 派发 `--isolation clean_room` 只读流 | 仅传入成稿与目标读者身份（不附内部草稿或倾向），专门挑出叙事断裂、概念门槛、逻辑自相矛盾与不可读段落。 |
| 3. 事实核对与定稿 | 偏严谨的代码或数学审查流 + 主会话终校 | 逐式核对源码实现、数值表、参考文献与公开脱敏；正式文档最终验收按全局规则 R2 运行 `check-grounding --target . --strict --doc-hygiene`（`--hygiene-only` 仅作初稿与改稿中段的结构、图件及定理空壳快速辅助检查，不替代整仓事实锚定）。终校**只修技术错漏**，不把通顺表述改回生硬措辞。 |
